## 必須対応3: `doctor`コマンドを実装する

次のコマンドを追加する。

```text
needs-detector doctor
```

プロジェクトの破損、未完了、整合性問題を診断し、人間が次に取るべき行動を判断できる出力を返す。

### 必須診断項目

- `project.yaml`の存在・YAML構文・必須キー
- `sources/index.yaml`と実ファイルの整合
- ペルソナYAMLのPydanticまたは同等のスキーマ整合
- alternatives YAMLのスキーマ整合
- インタビューYAMLの必須項目
- 引用文と原文行番号の再検証
- Manualジョブ台帳の構文とrequest/responseファイルの存在
- waitingジョブ、failedジョブ、二重job_id、未知target
- `learn_results.yaml`とStep状態の矛盾
- Step 4 completedなのに実インタビューが0件という不正状態
- AI補完記録の工程、成果物、job_idまたはfixture参照の整合
- 最終レポートが現在の成果物より古い可能性
- プロジェクト外パス参照が保存されていないこと

### 出力形式

人間向けの標準出力に加え、次を実装する。

```text
needs-detector doctor --json
```

JSONには最低限、次を含める。

```json
{
  "status": "ok|warning|error",
  "errors": [],
  "warnings": [],
  "checks": [],
  "next_actions": []
}
```

### 終了コード

- 0: errorなし
- 1: 修復または確認が必要なerrorあり
- warningのみは0とする

例外のスタックトレースを通常利用者へそのまま見せず、安全で具体的な原因を表示する。

## 必須対応4: `next`コマンドを実装する

次のコマンドを追加する。

```text
needs-detector next
needs-detector next --json
```

現在の状態、成果物、待機中Manualジョブ、人間確認ゲートから、次に実行すべき操作を最大3件まで提示する。

### 例

- idea未登録: `add-idea`
- source未登録: `add-source`
- Step 1未開始: `draw`
- Manual Draw回答待ち: 対象job_idを示し`import-llm-response`
- ペルソナあり、代替品なし: `explore`
- Guideなし: `interview-guide`
- インタビュー0件: 「現実の顧客へインタビューし、匿名化記録をadd-interviewする」
- Manual Learnの一部回答待ち: 未取込targetとjob_idを表示
- Learn完了、レポートなしまたは古い: `report`
- 完了済み: 新しいインタビュー追加または未確認事項の検証を提示

### 重要条件

- インタビュー0件で`learn`や「検証完了」を勧めない。
- Mockデモの完了をCustomer Problem Fit確立と表現しない。
- `doctor`でerrorがある場合は、通常ワークフローより修復を優先する。

## 必須対応6: 合成デモを実データと明確に分離する

`examples/`または同等の場所へ、wheelインストール後でも再現できる合成デモ手順を置く。

### 条件

- ファイル名・README・レポートの全てで`synthetic`または「合成データ」と明示する。
- Dataset A/Bは機能確認用であり、市場やCPFを証明しないと明記する。
- 実インタビュー用テンプレートと混在させない。
- テストデータ中の架空発言には、合成データであることをメタデータとして持たせる。
- 合成インタビューを読み込んだプロジェクトは、レポート上で「実顧客検証済み」と表示しない。

必要なら、プロジェクトまたはインタビューへ次のようなデータ区分を追加する。

```yaml
data_classification: synthetic | real | unknown
```

実装方法は自由だが、既存プロジェクトとの後方互換性を考慮する。
