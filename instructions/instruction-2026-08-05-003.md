# Antigravity運用変更の確認

## 目的

作業結果の保存先を、従来の共通ファイル `result.md` から、指示書ごとに分離した結果ファイルへ変更する。

## 作業前の必須手順

1. `git status --short` を実行し、未コミット変更を確認する。
2. 未コミット変更を勝手に破棄、上書き、stashしない。
3. 作業ツリーが安全な場合だけ、`git pull --ff-only origin main` を実行する。
4. pull後に `.agents/AGENTS.md` を読み直す。
5. 本指示書が `instructions/` 内で最新の指示書であることを確認する。

## 実施内容

1. `.agents/AGENTS.md` の新しい結果ファイル規約を確認する。
2. 今後は、各指示書と同じ日付・連番の結果ファイルをリポジトリ直下に作成する運用へ切り替える。
3. 本指示書の実行結果は、必ず次のファイルへ記録する。

```text
result-2026-08-05-003.md
```

4. 従来の `result.md` は過去記録として残し、本作業の結果を追記しない。
5. `DESIGN.md`、`TESTPLAN.md`、`agent-a-design.md` が存在するか確認する。
6. この指示ではプロダクトコードの実装・変更は行わない。

## 結果ファイルに記録する内容

`result-2026-08-05-003.md` に、最低限次を記載する。

- 状態: `COMPLETED` / `BLOCKED` / `FAILED`
- 対象指示書
- `git pull --ff-only origin main` の結果
- `.agents/AGENTS.md` を確認したこと
- 新しい結果ファイル命名規則を理解したこと
- `DESIGN.md`、`TESTPLAN.md`、`agent-a-design.md` の存在確認結果
- 変更したファイル
- テスト未実施の場合は、その理由
- commit SHA
- push結果

## コミットとpush

1. `result-2026-08-05-003.md` を作成する。
2. `git status --short` と `git diff` で変更内容を確認する。
3. 今回必要なファイルだけをステージする。
4. 次の趣旨のメッセージでコミットする。

```text
docs: confirm numbered result file workflow
```

5. `git push origin main` を実行する。
6. pushに失敗した場合は完了扱いにせず、結果ファイルへ理由を記録する。

## 完了条件

- 作業前にpullした
- `.agents/AGENTS.md` を確認した
- `result-2026-08-05-003.md` に結果を書いた
- `result.md` を変更していない
- 変更をコミットした
- `git push origin main` が成功した
