## 外部監査で確認された不具合

### 不具合1: doctorが正常な資料をmissing扱いする

`ProjectService.add_source()` は資料を次へコピーする。

```text
<project>/sources/<file_name>
```

一方、現在の `DoctorService` は `sources/index.yaml` の `file_name` を次のように解決している。

```text
<project>/<file_name>
```

このため、CLIで正常に `add-source` した資料でも `doctor` が missing と判定し得る。

### 不具合2: nextが資料未登録を検出できない

初期化直後から `sources/index.yaml` が存在するため、次のようなディレクトリglobでは資料登録済みと誤判定する。

```python
list((project_dir / 'sources').glob('*.*'))
```

`index.yaml` だけがある状態は、資料0件である。

### 不具合3: レポートが存在しない引用元を表示する

現在のレポートは、実体が `interviews/interview_<target>.yaml` だけであるにもかかわらず、次のような引用を表示する。

```text
[interview_<target>.md:L1]
```

存在しないファイルを出典として表示してはならない。また、YAML内部の `content` の行番号と、YAMLファイル物理行番号も一致しない。

### 不具合4: mixedデータをrealとして集約する可能性がある

realインタビューが1件でもあると、syntheticまたはunknownが同じプロジェクトに含まれていても集約結果が `real` になり、警告が消える可能性がある。

実データと合成データの厳格な区別という009の目的に反する。

## 必須修正1: source参照の共通実装

資料の解決方法を複数サービスへ重複実装せず、共通関数または小さなサービスへまとめる。

### 必須仕様

- `sources/index.yaml` の `file_name` は `project_dir / 'sources' / file_name` を基準に解決する。
- 絶対パスを拒否する。
- `..` を含むパストラバーサルを拒否する。
- Windows形式の絶対パス・UNC・ドライブ文字も拒否する。
- シンボリックリンク等によるプロジェクト外参照も検出する。
- indexのroot、`sources`、各entry、`file_name` の型を検証する。
- 同一ファイル名または同一IDの重複をwarningまたはerrorとして明示する。
- `add_source`、`DrawService`、`DoctorService`、`NextService` が同じ解決規則を使う。

### 必須テスト

1. `add-source` した正常な資料を `doctor` が `ok` と判定する。
2. indexだけで資料0件の場合、`next` が `add-source` を提示する。
3. 正常な資料が1件ある場合、`next` は資料未登録とは表示しない。
4. missingファイルをdoctorがerrorにする。
5. `../outside.md`、絶対パス、Windows絶対パス、UNCを拒否する。
6. malformed indexを安全な具体的エラーにする。

## 必須修正3: 実在する引用元アーティファクト

インタビュー原文の行番号を安定して参照できる、実在する原文アーティファクトを保存する。

### 推奨構成

```text
interviews/
  raw/
    <interview_id>.md
  interview_<interview_id>.yaml
```

設計上同等なら別構成でもよい。

### 必須仕様

- `add-interview` 時に、入力原文を改変せずrawアーティファクトへ保存する。
- derived YAMLには少なくとも次を保存する。

```yaml
source_file: interviews/raw/<id>.md
source_sha256: <sha256>
content: <互換性のため保持可>
```

- 引用検証はrawアーティファクトの実際の行を基準にする。
- レポートは実在する相対パスを表示する。

```text
[interviews/raw/<id>.md:L3]
```

- 表示したファイルと行番号を開けば、その引用文字列が実際に存在すること。
- rawアーティファクトが変更、欠落、hash不一致の場合、doctorはerrorを出す。
- rawファイルおよびderived YAMLの保存先はプロジェクト外へ出られない。
- 同名入力による上書きを防ぐ。一意IDまたは明示的な重複エラーを使う。

### 既存プロジェクトの後方互換

既存のYAMLに `source_file` がない場合は破壊しない。

次のいずれかを実装する。

- doctorでlegacy warningを出し、明示的なmigrationコマンドまたは修復方法を提示する。
- 安全にrawファイルを生成できる場合だけ、自動または明示的migrationを実装する。

既存YAMLの `content` からrawを作る場合、元原文と完全同一である保証がないことを文書化する。黙ってreal原文として扱わない。

### 必須テスト

1. `add-interview` 後にrawとYAMLが存在する。
2. rawのsha256とYAML記録が一致する。
3. reportの引用パスが実在する。
4. report記載行へ実際に引用文字列がある。
5. raw改変をdoctorが検出する。
6. raw削除をdoctorが検出する。
7. rawのパストラバーサルを拒否する。
8. 同名インタビューを上書きしない。
9. legacy YAMLを安全に扱う。

## 必須修正4: データ区分の集約を正確にする

個々のインタビュー区分と、プロジェクト全体の集約表示を分ける。

### 必須仕様

集約結果は少なくとも次を区別する。

```text
real
synthetic
unknown
mixed
```

- realのみ: `real`
- syntheticのみ: `synthetic`
- unknownを含む: 原則 `unknown` または `mixed`
- realとsyntheticが混在: `mixed`
- realとunknownが混在: `mixed`
- syntheticとunknownが混在: `mixed` またはunknownを明示した詳細表示

### 表示条件

- `status`、`doctor`、`next`、reportの全てで同じ集約結果を使う。
- `mixed`、`synthetic`、`unknown`では、実顧客検証済み・CPF確立・市場成立とは表示しない。
- `real`でも、人数やAI評価だけでCPF確立・市場成立とは表示しない。
- JSONには可能なら内訳を含める。

```json
{
  "data_classification": "mixed",
  "classification_counts": {
    "real": 1,
    "synthetic": 1,
    "unknown": 0
  }
}
```

### 必須テスト

- realのみ
- syntheticのみ
- unknownのみ
- real + synthetic
- real + unknown
- synthetic + unknown
- interview 0件でproject.yamlがsynthetic

各ケースでstatus、doctor、next、reportの表示が一致することを確認する。
